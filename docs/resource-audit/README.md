## 开放范围纠正（2026-11-06）

早期 `generate.py` 与 `loading-chain/audit.py` 使用临时数据库和本地可支持集合，没有读取生产运营日程，不能作为“生产已开放关卡完整审计”。最终替换报告使用生产怪物兼容清单；角色型敌人审计遍历原主表全部角色型记录、读取生产包并验证HTTP，也不等同于按生产开放列表覆盖全部关卡。

本次直接只读查询生产部署配置指定数据库：revision 40，36组开放活动、103个开放活动关卡。与现存 `loading-chain/results.json` 中228个关卡比较，有12个生产开放关卡不在旧范围：25061、25062、25063、25073、25074、25075、25076、25077、25078、25079、25080、25081。因此不能声称旧加载链报告已经完整覆盖当前生产开放范围。这是当前范围比对，不能反推这些关卡在旧报告生成时就已开放；也不表示这12关的资源一定缺失。

后续按“已开放”统计须读取生产实际 runtime_config，记录 revision、检查时间及 is_open 判定；本地可支持集合只可称“可支持范围”，生产资源兼容清单只可称“已部署替换范围”。以上12关尚未在本次执行完整资源依赖审计，历史报告保留追溯，不以改标题伪装重新审计。

上述12关已完成[生产范围补充审计](production-training-20261106/README.md)：生产revision 40，41条敌人记录，22个下载包HTTP/哈希/导出/具名贴图及递归依赖核查通过，本地动作绑定与来源哈希复核通过。未发现需新增修复的上述资源缺口；仍不代表Android实机通关验收。旧索引差异与本次生产证据分列，不能沿用旧catalog的缺包数量作为当前缺口。
