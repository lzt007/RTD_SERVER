# 20710「召喚」闪退调查与服务端资源修复方案

日期：2026-11-05。状态：两处资源缺陷已隔离：原生活动标记与缺少根Animation。v3已由用户部署生产；v4根动画候选在模拟器越过转换并完成一次战败流程，尚未部署，胜利结算和真机验收未完成。

## 结论与修改范围

修复入口是服务端分发的 AssetBundle。客户端 APK 无需加入永久绕过逻辑。调查使用的客户端边界日志、状态观察、跳过卸载及禁用敌人均为模拟器诊断实验，不属于交付修复。

生产分发的推测书本包 ms00_book_el_03，其 GameObject pathID603（move）、609（ast_ms00_book_el_03）的 m_IsActive 为1。将模拟器实际缓存中的这两个字段改为0，在恢复正常敌人激活、正常音频卸载后，20710可以进入 GameStateField，controlsUnlocked=true；还原原缓存则再次出现入场 Pure virtual function called。重启后再次使用修正缓存，点击网络重连后也成功进入关卡，脚本停止输入后游戏进程仍存活。

因此，书本包活动标记是本次入场闪退已被对照支持的资源触发因素。这与旧 Unity 3.5 资源的原生标记要求及此前狼／史莱姆修复经验一致。但尚未用符号化原生栈证明具体失效的虚表对象，不应把推测的引擎内部机制写成定论。

入场成功不等于整关通过：移动后角色敌人由地图书本切换战斗角色时仍退出，最后可见 EnemyManager.ChangeUnitEnemy、方向动画加载；最新一次日志也出现 AnimationData/Motion/null。该路径的资源／动作映射尚未完成隔离，不能据此断言 null 动作就是唯一根因，更不能通过更改真实敌人配置掩盖问题。

## 复现环境与证据

客户端2.4.0，Unity3.5.6f4。Android16真机最初复现；Android9 Google APIs x86模拟器借助ARMv7翻译亦复现同类断言，因此不是Android16独有故障。模拟器的ARM翻译层回溯存在重复偏移，不能视为可靠ARM调用栈。

真机首次记录：22:31:40.221出现level3 Position out of bounds；22:31:40.877最后的EffectName警告为ef_atk_magic_01_ms；22:31:41.590出现Pure virtual function called；22:31:42.319 UnityMain SIGABRT。

Android9原始缓存入场：日志11-04 16:07:54.952（宿主机11-05 00:07:54）同类断言，PID5397。第二轮PID9809，第三轮PID10547均重复。还原原缓存对照PID14032，仍为Pure virtual function called / SIGABRT。

修正缓存：PID13507到达可操作场景，随后旧脚本自动移动并在角色转换时退出。后续新增quest-entry目标，到达GameStateField即停止输入；重新启动后的PID4969再次入场成功并取得场景截图。期间TitleMenu3001停顿实际上有网络失败重连弹窗，手动重连后恢复，不应归为资源加载死锁。

原始日志、截图、APK、签名和缓存仅保留在Git忽略的 logs/20710-investigation；其中可能包含运行环境或账户信息，不提交。关键文件：reproduction-223142.log、api28-crash-all.log、api28-second-crash.log、api28-third-crash.log、ab-original.log、repro-book-inactive-2.log、reconnect-entry.log、entry-idle.png、move-isolation-live.log。

## 配置和静态排除

关卡20710的原始enemy_table_id=14420。普通敌人41028是角色敌人（chara_kind301、symbol12、g_id126、atk_ef14），10303是暗属性小龙；Boss是31030（ms00_death_01），41033是death槽，不能误称Boss。

生产有效重建快照中10303、41033仍使用临时占位ms02_four_un_01_zako。生产恢复清单主要是18个狼／史莱姆包，该关卡未直接引用这些包；没有证据将本故障归咎于新暗龙模型。快照来自内存初始化与生产配置，不等于客户端实际主表转储，实际缓存命中仍需独立核对。

设备APK的level3及相关sharedassets与原APK字节一致；非Mono对象静态读取无越界。Android9教程也出现level3越界日志，却能战斗通关，因此该错误不是目标闪退的充分条件。原与补丁Assembly-CSharp实例字段顺序、类型及序列化属性比较无变化。效果ef_atk_magic_01_ms依赖闭包静态读取无悬空引用，且运行加载和实例化均返回；不能仅凭最后一条效果警告判坏。

## 服务端资源修复方案

1. 保留现有生产原包与实际响应SHA256，先在隔离目录构建候选，不直接覆盖已有真实资源。
2. reconstruct_shingetsu_book.py已加入所有GameObject原生活动标记0，并为六色候选生成互不相同的新内部资源身份；记录源SHA256、导出名、活动字段变化和输出SHA256。原始主表数值、敌人类别、掉落、地图均不改。
3. 候选位于忽略目录book-native-v2，六色已生成validation.json。它们尚未经完整运行验收，不应称生产可用版本。缓存字段对照只直接验证了03，不能推广为六色全部运行通过。
4. 发布前分别验证本地命中和远端首次下载；核对响应SHA256、内部CAB名、导出对象和客户端缓存版本。更新服务端资源版本或受控失效缓存，避免用户继续命中旧包。
5. 当前不部署：先解决角色转换退出，并完成下述验收。无需把跳过Unload、隐藏敌人或诊断日志补丁带入正式客户端。

## 防复发与验收要求

- 旧Unity资源必须按目标客户端原生格式验证，UnityPy能解析只代表静态可读，不代表引擎生命周期合法。原型活动标记、对象归属、导出依赖闭包、骨骼／动作、独立CAB身份均须检查。
- 角色敌人必须同时审计地图书本包、角色分组包、角色导出名、方向动画和动作映射。原角色资源存在不代表地图标记及动作链完整；不得只检查敌人包。
- 日志应记录调用前后与具体资源路径。流式日志可能在崩溃末尾截断，必须补读完整logcat，不能因缺AFTER就立即归因。
- 自动化要覆盖网络失败弹窗，并区分入场停止、静置、移动、遇敌转换、战斗、结算、退出／重入。旧教程脚本自动移动曾掩盖入口与转换两个阶段，应使用独立目标。
- 验收依次为：静态字节／引用核对；Android9冷缓存下载；热缓存重入；入口静置；地图移动与角色转换；普通敌人及Boss战斗；通关结算；释放／再次进入；正常关卡回归；最后Android16真机验证。任一未过均不得记为整关修复。
- 六色候选须逐一验证；当前仅入口03有对照证据。还需验证战斗转换后的角色动作映射、模型对象与释放生命周期，定位后续退出的确切信号及调用。

### 战斗转换边界扩展

111处边界诊断包复测PID10021：Enemy角色动作CrossFade已返回；ChangeUnitEnemy的方向动画AddClip、set_clip均返回；之后旧地图敌人Enemy.UnLoad的set_clip(null)、Destroy(AnimationController)返回，随后退出。证据为忽略目录animation-boundary-crash.log。MotionData本身包含字面值null，不能把AnimationData/Motion/null当作唯一根因。下一步隔离旧书本清理／延迟销毁与新角色首帧更新；此时尚未确认具体触发对象，不发布客户端绕过。

### 跳过旧敌人清理的诊断对照

仅在模拟器诊断副本将Enemy.UnLoad函数体替换为日志与返回，其余逻辑保留。入场后单次点击移动，随后观察到GameStateBattle且PID11165仍存活；基线在转换后退出。此次补读日志中跳过标记已缺失，不能单凭状态就断言因果已完全确立，需连续采集并重复对照。该绕过会改变资源释放行为，不是正式修复，不部署生产。下一步拆分动画清理、控制器销毁、材质解绑，并核对推测书本对象的组件归属与依赖共享。

## 第二处根因：书本根对象缺少释放所需Animation（v4候选）

生成器v3仅在move子对象挂Animation；根GameObject609只有Transform与SkinnedMeshRenderer。SetupEnemyComponent只给move附加AnimationController，不会补根Animation。Enemy.UnLoad清理子对象后，无条件读取根对象animation.clip。因此“能实例化、有子对象动画”不能满足完整资源契约。

152处调用边界复测PID15545：UnLoad IL008c Component.get_animation正常返回，紧接IL0091 Animation.get_clip只有BEFORE而无AFTER，随后进程退出。此调用对应缺少Animation的根对象。日志root-animation-baseline-full.log与原APK托管代码路径互相吻合；无需把MotionData中的字面值null误判为动作配置损坏。

仅修改模拟器缓存：保留原move动画1184，新增空Animation1300，m_GameObject指回根609，根组件列表加入该对象；未改材质、网格、动作映射、主表或客户端清理行为。复测PID16136的同一get_clip调用正常返回，进程存活并进入战斗。自动战斗随后运行到GameStateGameOver，partyLife=0，说明低等级测试队伍战败；这是战斗结果，不是原转换时的进程退出，仍未证明通关结算通过。

该对照支持第二处资源结构根因：推测模型遗漏客户端释放路径需要的根Animation。服务端修复应在生成包中补组件；不能永久跳过UnLoad、隐藏敌人或修改原敌人类型／数值。

reconstruct_gacha_book.py候选升级为root-animation-v4：复制旧Unity模板的空Animation到独立pathID1300，保留move组件；将新对象加入导出预加载依赖；新内部身份防止与旧包同载冲突。validate_book增加根组件引用与反向归属检查；六色测试逐个检查根和move各有一个归属正确的Animation。相关3项资源测试、1项准备流程测试全部通过。Windows测试改为从字节加载UnityPy，避免临时目录因文件句柄占用清理失败。未运行全仓回归，不宣称全仓通过。

本次候选未部署生产。发布前仍须六色候选构建／HTTP与缓存版本核对，正常关卡回归，书本转换和普通／Boss战斗，胜利结算、失败退出、重入、最终Android16真机验收。当前实际运行对照使用03的缓存候选，不能替代六色完整运行验收。

### 防止同类遗漏

模型契约检查必须覆盖创建、使用、转换和释放。逐方法反查根对象与子对象分别被访问的组件；对无条件getter必须提供合法组件，即使模型显示阶段不使用。静态依赖闭包和对象数量检查不能代替组件位置与归属校验。不要只为让旧“11对象”校验通过而拒绝必需的新组件；对象集合约束应来自客户端契约。后续替代模型评审须附根／子对象组件表及释放路径说明，并至少跑一次转换或销毁对照。
