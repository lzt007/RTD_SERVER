# 敌人模型修复经验与纠错记录

更新：2026-11-05。适用于普通敌人、模型式Boss及复用玩家角色的Boss。当前证据入口见上级README；原始记录和文件不覆盖。

## 素材匹配顺序

同时检索现阶段打包APK、旧Unity缓存、新7.0.1.0 APK和新缓存。既有临时替代不是“已经修完”的证据；发现更精确原素材应重新评估。先精确模型与贴图，其次种族/子种正确，再属性，再等级；只有完全找不到同族时才可跨族，并明确记录。角色包、非ms命名、无名对象和实际材质引用不能漏查。

ms只是命名线索，不是扫描白名单或加载类型。先由原type判定加载方式，再解析模型字段。kn/ar/la/wz、swd/grt/gun等职业/武器字段要与角色主表对应；220/330等前缀和末尾01/02未经证实不能当等级。贴图名不必与模型名相同，例如英灵王e01_la_lan_holy_01使用_full、_wpn两张纹理，均在生产411-420包内；不能仅因同名Texture2D未命中就判缺图。

## 角色型Boss：复用兽王经验

原IsUnitEnemy类型为22、24、30、31、33、37，不由ms判定。本次186条角色型敌人共184个模型，其中183个不带ms；185条非ms记录在生产中保留原model/texture，不能说它们都被替换成野猪。全部183个均有同名角色对象，新缓存也提供其中135个。角色主体存在还要核对地图书本、角色分组、动作和特效。

symbol10..15选择书本1..6，其余选6。gid>0时组包起点为((gid-1)//10)*10+1，按原模型名Load；gid=0时使用独立模型包并Load ast_原模型名。兽王先前关键缺口是书本，不能因本体在151-160包中就认为整条依赖已齐。现49个角色/独立模型/书本包HTTP哈希均已核对。

ChangeUnitEnemy会镜像根X、设Z=.01和Y=.6，再给根Animation加入el_boss_tob（六人队用_6）。因此根Animation不可遗漏，也不能仅凭Y180副本名称就强选所谓敌方面向。多条同名导出须保留证据，原型激活状态、实例生命周期与普通怪物相同重要。

## 动作必须按原映射核对

奥尔·加迪亚41317虽叫ms03_sen_olgadia_01，原type33/gid0仍走角色型路径。原APK实际有org_wait_swd_01、org_atk_swd_01；两者各19条曲线路径均匹配当前move骨架。el_boss_tob及_6只操作根路径，当前根Animation可绑定；攻击特效ef_atk_blade_02_ms也存在。旧验证器按ms03_sen猜名误报not_present_in_original_apk，现按精确模型对应原type33动作验证，并要求两个clip都确实来自原APK。

ms03_org_run_01有两条anckle/ankle拼写差异，单独保留待核项。尚无证据type33使用该run分支，不能为了这个差异重命名骨骼，破坏已正确匹配的待机和攻击。嵌入four_tob并不证明入战动作错误，因为原客户端会重新添加toBattle。此项修正的是验证器，不需要改资产或伪造原图。

## 几何、材质与等级替代

狼外形已获用户确认，不能再把设计解释为缺头缺腿。旧碎块/多余原型应检查逐导出引用闭包、预加载表、原生激活标记及独立CAB，不能删正常面片掩盖。多材质模型保留每个材质自己的纹理，尤其武器不可误绑身体图。透明度、UV、蒙皮和动作采样均要回读对照。

只对缺失原等级、手动放大的替代采用Lv2=1.3、Lv3=1.6、Lv4=1.9（相对Lv1）。源是Lv2时按1.6/1.3等比例换算；不能把已放大输出再乘一次。原生高等级模型、只染色和影型不能统一强加倍率。影型用对应同族同属性普通型降饱和度/明度，并保留alpha。

同族替代不等于原Boss完整恢复。Mind Boss、巨龙头、达哈卡部分变体、樱花达哈卡、神龙及特殊龙变体仍有专属图稿缺口，见Boss报告。当前鱼类5项用河豚是明确跨族替代，不能由“只有鱼跨族”推出“全游戏原资源完整”。

## 发布、计数与验收

生产兼容模型为278包=逐族批次271+松鼠7。本地287包另含9个未列入生产怪物清单的辅助资源，不得整份同步导致意外发布。等级调整17包；其余生产261包、本地270包分别统计，原优先目录92包保持。来源数量、模型数量、敌人记录数与文件数量不能相加混用。

窄范围发布：备份文件及SQLite一致性副本；比较发布前、候选和发布后的全部有效主表、地图、活动、开放和运营配置；逐包核对真实HTTP哈希，检查服务健康。离线脚本不属于服务运行依赖，不将UnityPy加入生产服务环境。新增审计元数据可以修正，但不能借此改原始属性、数值、等级、掉落或开放条件。

固定版本客户端可能继续使用旧缓存，改SHA或CAB不保证重新下载。实机复测执行取得最新数据并重启、新入关卡。模型显示、完整依赖、资源释放和通关结算分别验收；通关闪退仍未解决，不得以离线测试/HTTP正常声称修复。
