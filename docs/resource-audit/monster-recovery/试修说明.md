# 狼与史莱姆模型替换说明

后续相关工作必须先阅读 [模型替换流程](模型替换流程.md)。2026-11-04 用户确认最终狼模型显示正确，银色史莱姆显示正常；**完成关卡时闪退仍未解决，本次仅模型替换。**

本次范围仅为当前主线与已完成重建、可配置开放的活动所引用的狼及史莱姆。未扩大关卡开放范围；未分析新压缩包内的两个 APK。

## 当前实现

| 缺失类型 | 处理 | 原件与推测的界限 |
|---|---|---|
| 狼 Lv1/Lv2，四属性 | 提取新备份 330_ms01_wolf_lv1_[f/w/h/d]_01 的网格、骨骼、纹理；转换到旧 Unity 3.5 格式 | 素材来自备份；与旧等级的对应为推测，两级共用外形 |
| 狼 Lv3/Lv4、四属性特殊狼 | 使用新备份 550_ms01_wolf_[f/w/h/d]_01 | 同上，特殊型和等级独有外形尚未找回 |
| 普通史莱姆 Lv2/Lv3/Lv4、特殊水史莱姆 | 原 APK 普通 Lv1 模型与对应四属性贴图的同族复用 | 原始素材，等级及特殊外形为临时替代；不推测修改大小 |
| 银史莱姆 Lv1–Lv4 | 复用原金史莱姆几何、蒙皮及 UV，将原金贴图转为灰银 | 推测重着色，不是找回的原银史莱姆画稿；Lv2/Lv3 使用 Lv1 几何 |
| 金史莱姆 Lv2/Lv3 | 复用已有金 Lv1 外形 | 等级独有外形未找回 |
| 原普通 Lv1、金 Lv1/Lv4 | 使用原件 | 不替换 |

新备份的带翼史莱姆确实存在，但当前可开放关卡的本次引用集合没有该模型，因此未把它强行替换为普通史莱姆，也未将其纳入本次 18 个输出包。各包、纹理来源、SHA-256 和推测原因见 `config/monster-recovery.json`；实际输出位置是 `resources/reconstructed/monsters/bundles/`（本地生成资源，不进 Git）。

可用 `scripts/report_monster_recovery.py` 生成本地 `兼容修复预览.html`：用实际输出包的网格与贴图生成的离线静态预览，不含动作、阴影和游戏内尺度。

## 启用试修

这是默认关闭的独立试修层。**API 进程和资源服务进程都需要设置 `RTD_MONSTER_RECOVERY=1` 并重启**，保留当前各自其余启动参数与活动修复开关。例如资源服务可以在原启动命令前增加 `RTD_MONSTER_RECOVERY=1`。不需重新打 APK。

资源服务优先读取原包，仅在原文件缺失时提供清单中校验通过的兼容包。有效敌人主表仅恢复当前可开放关卡引用且已准备兼容包的原模型/纹理名，重新生成主表校验值。属性、等级、类型、数值、奖励、掉落、地图、开放条件均不修改。

关闭：两进程去掉该环境变量或设为 `0` 后重启，即回到原有占位策略。不会改写原始主表与原资源。

## 复现与验证

完整构建步骤及最终八个狼包的清单合并规则见 [模型替换流程](模型替换流程.md)。仅运行基础转换器会产生中间包，不能直接发布；正式狼修订为 `wolf-native-activation-v4`。

构建输入的可开放模型集合是开启既有活动重建后，从有效主线/活动关卡的敌人表全部 18 槽、Boss、Death 引用回查原敌人表得到；不是按名称扫全主表。原客户端 SetupChooseQuest 创建 EnemyArrangeTable，GetUniqueEnemyList 遍历该表，再由 LoadEnemyAssetBundle 预加载，因此不能仅按地图实际出现的槽位缩小依赖。启用层在运行时会再次按当前实际可开放集合限制变更。

加载链依据为原客户端 `AssetBundleLoader` 定义、`EnemyManager.AddEnemy` / `SetupEnemyComponent`、`Enemy.SetEnemyParameter`。包导出 `ast_<原模型名>` 和原纹理名；保留 `move` 节点与骨骼层级。普通史莱姆、狼、银史莱姆分别按 ActionAssign 的类型偏移行 37、39、50 使用旧客户端待机/攻击动作，所需路径均匹配。Unity 5 新 shader 不直接移植，使用原旧 Android shader 与相应材质格式。

每个生成包均重新解析，校验旧序列化版本、全部 PPtr、网格/UV/索引/蒙皮/绑定矩阵写回一致性、权重和骨骼索引、每套骨架动作路径、RGBA 像素写回一致性。内部序列化文件名按输出模型独立生成，避免同载冲突。

有效配置对比覆盖原活动重建开/关两种组合；HTTP 测试包含旧客户端下载路径、开关、完整字节、损坏包拒绝、原文件优先。另见[验证结果](验证结果.md)及[有效引用修复记录](有效引用修复记录.json)。

用户已在实际客户端确认银色史莱姆和最终狼模型显示正确。各等级/属性在所有关卡中的完整回归仍未穷尽；通关闪退仍存在，不能由模型验收推断结算已修复。
