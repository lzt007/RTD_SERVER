# 书本替代包加载闪退排查

用户反馈：清缓存获取六色自制书本后，进入「歴史の闇を知りし者」（20710）在加载阶段整个应用退出。重新启动出现恢复战斗提示，选否后仍被抽卡／商店的 pending-battle 守卫拦截。

## 已确认与未确认

资源服务确实提供了新书本文件；HTTP 成功不能证明 Unity 能成功反序列化、实例化及渲染。当前主机没有 adb，未取得设备 logcat/tombstone，不能确定闪退指令或声称闪退已根治。

v1 生成器在 Unity 3.5.6f4 资产中写入六索引 triangle-list 并声明 triangleCount=2。旧版解码得到三个非退化面，其中有反向重叠面；原资源各子网格使用 isTriStrip=2。旧验证仅看声明的三角数量和顶点／UV，没有验证实际面，因而漏检。

v2 使用原资源的四索引 strip（0,1,3,2），声明 indexCount=4、triangleCount=2、isTriStrip=2。验证实际解码恰两面，覆盖四边形且不重叠。单骨、权重、bindpose、move/Animation 等绑定未改变。不将此静态格式修正等同于已经证明 native 闪退根因。

新增面覆盖回归在 v1 失败（3 != 2），v2 通过；六色包重建并使用独立 v2 内部文件名，继续保留真实抽卡书本像素与推测标记。

## 战斗记录与菜单

原版客户端主动放弃或拒绝恢复可清本地恢复状态，不必立即删除服务端待恢复记录。服务端有新 UUID 订单替换旧 run 的原子机制。pending 记录不能作为菜单禁用条件。

移除抽卡、恢复体力、容量扩张的全局 pending-battle 守卫。资金、容量上限、订单冻结、重试幂等和结算校验保持。新增扩容回归先复现 8197，修后检查冻结战斗不变及跨重启不重复扣费。无新增客户端协议。

本次按用户明确要求，单独备份并清理报告账号的 20710 残留 run：标记 abandoned，废弃订单，清 battle 缓存；严格验证货币、体力、库存、进度及其他账号字段不变。该临时恢复不等于正式修复，不在登录时普遍清记录。

## 回归边界

扩大回归时发现 test_quest_content 的旧 experimental-content 断言失败（期望 20101 关闭）。相同测试在未修改的生产代码独立运行也失败，属于既有测试／内容策略不一致；本次未改变关卡开放政策来迎合旧断言。发布使用相关菜单、幂等、续关、账户、新订单替换及书本／资源测试，并单独记录该既有失败。

仍需设备复测或崩溃栈；更新相同公开资源路径后，客户端已有 v1 缓存需要再次刷新。
