# 活动关卡批量重建

用户指定沿用神月已验证方法，要求持续推进，不开活动，最终输出可用／未能修复的逐关记录。本轮不重新选择实现路线。

范围：全部882条division=20000主表记录纳入审计；优先处理有归档攻略可对应、原始战斗表完整的单层副本。原始地图／掉落存在时永远优先；0、空掉落及无属性不是缺失。推测地图、普通怪位置、掉落概率和等级必须记录估算。未找到对应攻略、不支持的特殊协议或缺关键身份记录不能伪装完成。

方案：使用独立声明式攻略对应清单、缺失记录生成器及默认关闭内存叠加。源资源不改，不创建或启用活动排期；显式配置活动前，重建副本保持关闭。角色Boss先查真实角色包，连同书本标记／效果／动作的HTTP依赖一起核对；真实模型优先，确实缺失时才添加有来源的替代，已有文件不覆盖。

验收：原值保护、真实数据优先、地图可达性和原始挑战可实现性、逐关生成与领取掉落、结算及重试、角色资源依赖可解析、不开活动；文档包含每个ID的状态和具体阻塞原因。只完成离线／协议验证时标注待实机，不能宣称全面可玩。

风险：攻略未记录原地图和权重，重建不等于原版；共享原始掉落ID的推测必须一致，冲突必须拒绝并记录；资源名清单未命中不证明原资源文件缺失；不能把特殊多层关摊平成普通单层以躲过协议限制。

用户补充硬约束：原本正常关卡的有效数据和行为完全不变；共享敌人／掉落／资源的修复必须检查正常关卡引用，遇冲突不替换共享真值。用有效记录对比回归证明。

后续授权：用户随后要求为客户端测试批量开放，已部署84关、29组测试活动。上述“不开放”是初始修复阶段范围；最终生产状态与验证详见[生产测试开放记录](../../deployment-20261103-event-batch.md)。
