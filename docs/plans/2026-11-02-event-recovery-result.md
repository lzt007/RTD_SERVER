# 活动关卡恢复记录

已接入 69 个服务端战斗数据完整的活动关卡，包含七天全部 28 个每日限定关。

## 用户授权后的范围调整

允许缺失外观采用相近资源临时替换。新增 66 项敌人外观替换，优先同类相近等级模型和该模型可用的同元素贴图，无同类时使用已有占位模型。只修改 model/texture；所有战斗数值、技能、掉落与奖励引用保留。主表共享，同一敌人在其他关卡中的外观也受影响。

通过 RTD_VISUAL_RECOVERY=0 可禁用所有视觉恢复，此时缺少原资源的活动不会通过新增内容审计。

## 数据和资源

审计原 APK 全部 Data 文件与生产 bundles/cache，提取 5967 个资源名称；另按 GameObject/Texture2D 类型记录模型和贴图，MapTable 的 81 套场景依赖名称全部找到。没有编造缺失地图、敌人表或掉落表。

原始星期、前置通关、历史开放时间和 OrderStop 仍保留。旧限时活动需通过后台本地活动排期明确重开。新增支持开放条件 Cleared(7，自身已通关) 和 NotClear(9，指定关卡未通关)。

## 验证

新增测试覆盖逐关入场、首通、实际掉落领取、结算、挑战、重试幂等、续关、星期/前置条件、停开、条件7/9和资源缺失拒绝；视觉测试确认非外观字段完全不变。资源分发原清单1477文件校验通过。

未修改版本完整回归：269测试，58失败、1错误。第一轮修改版273测试同样58失败、1错误，失败标识完全相同；既有问题包括后台鉴权预期、旧内容门槛预期及图标依赖。最终完整回归280项，同样58失败、1错误，失败项目集合与基线完全一致。最终战斗及活动专项22项通过；生产运行环境使用临时数据库复验22项通过。

静态检查和服务端测试不能代替客户端实机完整战斗验收。
